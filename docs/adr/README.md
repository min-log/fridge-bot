# 결정 기록 (ADR)

구현하면서 내린 기술 결정을 하나씩 남긴다. 처음 기술 스택을 고른 이유는 [설계 문서의 결정 기록](../01_설계.md#1-결정-기록)에 있고, 여기에는 그 뒤 구현 단계에서 정한 것을 적는다.

| 번호 | 제목 | 상태 |
|---|---|---|
| [0001](0001-비밀값은-환경변수로만.md) | 비밀값은 기본값 없이 환경변수로만 받는다 | 채택 |
| [0002](0002-테스트와-로컬-실행은-testcontainers.md) | 테스트와 로컬 실행은 Testcontainers로 운영과 같은 DB·Redis를 쓴다 | 채택 |
| [0003](0003-소셜-로그인-결과는-1회용-코드로-전달.md) | 소셜 로그인 결과는 1회용 코드로 넘기고 토큰은 POST로 교환한다 | 채택 |
| [0004](0004-리프레시-토큰-redis-저장과-회전.md) | 리프레시 토큰은 Redis에 해시로 저장하고 쓸 때마다 회전한다 | 채택 |
| [0005](0005-액세스-토큰-검증은-리소스-서버.md) | 액세스 토큰 검증은 Spring Security 리소스 서버에 맡긴다 | 채택 |
| [0006](0006-가구-범위는-서버가-정한다.md) | 가구 범위는 요청 값이 아니라 로그인한 사용자로 서버가 정한다 | 채택 |
| [0007](0007-오류-응답은-problemdetail.md) | 오류 응답은 RFC 9457 ProblemDetail과 고정 code로 통일한다 | 채택 |

## 쓰는 방법

새 파일 `NNNN-제목.md`를 만들고 아래 항목을 채운다. 결정을 바꾸면 기존 파일을 고치지 않고 새 ADR을 쓴 뒤 이전 것의 상태를 "대체됨(NNNN)"으로 바꾼다.

```markdown
# NNNN. 제목

- 상태: 제안 / 채택 / 대체됨(NNNN)
- 날짜: YYYY-MM-DD

## 배경
## 결정
## 검토한 대안
## 결과
```
