# 0006. 가구 범위는 요청 값이 아니라 로그인한 사용자로 서버가 정한다

- 상태: 채택
- 날짜: 2026-11-25

## 배경
재고·영수증·통계는 모두 가구 단위 데이터다. 요청에 `householdId`를 받으면 매 API에서 "이 사용자가 그 가구 구성원인가"를 빠짐없이 확인해야 하고, 한 곳만 빠져도 다른 가구 데이터가 보인다.

## 결정
- API는 `householdId`를 경로·쿼리·본문으로 받지 않는다.
- 서버가 액세스 토큰의 사용자 ID로 소속 가구를 찾아 그 범위 안에서만 조회·변경한다.
- MVP에서는 사용자 한 명이 가구 하나에만 속한다 (`household_members.user_id` 유니크). 동시에 두 가구에 참여하려는 요청도 DB 제약이 최종으로 막고 409를 돌려준다.
- 구성원 추가·내보내기·초대 코드 규칙은 `Household` 엔티티 안에 두어 단위 테스트한다.
- AI Tool calling(9주차)에서도 같은 원칙으로, 도구 인자로 가구 ID를 받지 않고 서버가 `ToolContext`로 넣는다.

## 검토한 대안
- `/api/households/{id}/...` 형태 + 권한 검사: 여러 가구 소속을 지원하기 쉽지만 검사 누락 위험이 있다. 여러 가구 소속은 2차 범위라 지금은 단순한 쪽을 택했다.

## 결과
- 다른 가구를 지정할 방법 자체가 없다. 다른 가구의 구성원 ID로 요청해도 자기 가구에서 찾지 못해 404가 난다.
- 여러 가구 소속을 지원할 때는 "현재 선택한 가구"를 정하는 방식이 따로 필요하다.
- 테스트: 다른 가구 구성원 내보내기 404, 중복 소속 409 (`HouseholdIntegrationTest`).
