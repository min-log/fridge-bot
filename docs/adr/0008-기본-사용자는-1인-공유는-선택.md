# 0008. 기본 사용자는 1인, 가족 공유는 선택 기능으로 둔다

- 상태: 채택
- 날짜: 2026-11-25

## 배경
설계 초안은 "가족과 함께 쓰는 냉장고"를 전제로 가구 공유를 핵심 기능으로 잡았다. 2주차에 가구 생성·초대·참여까지 구현한 뒤 기획 문서를 쓰면서, 실제 사용자는 혼자 사는 본인이라는 점이 전제와 맞지 않았다.

## 결정
- 기본 사용자는 1인으로 보고, 화면과 흐름도 혼자 쓰는 경우를 먼저 맞춘다.
- 이미 만든 가구 구조(초대 코드, OWNER/MEMBER)는 유지한다. 원하면 가족을 초대해 같은 냉장고를 함께 볼 수 있다.
- 재고·영수증·통계는 계속 가구 단위로 저장한다 ([0006](0006-가구-범위는-서버가-정한다.md)).

## 검토한 대안
- 개인용으로 단순화하고 공유는 2차로 미루기: 지금은 더 단순하지만, 나중에 공유를 넣으려면 모든 데이터의 소유 단위를 사용자에서 가구로 바꿔야 한다.
- 가구 구조는 남기고 초대 기능을 화면에서 숨기기: 쓸 수 있는 기능을 일부러 감출 이유가 없었다.

## AI 제안과 내 결정
- AI 제안: 설계 초안에서 "실제로 가족과 함께 씀"을 사용 단위의 이유로 적음 (실제 상황을 확인하지 않은 가정)
- 내 결정: 기본은 1인, 함께 쓰는 것은 "같이 쓸 수도 있으면 좋겠다" 수준의 선택 기능
- 다르게 한 이유: 실제 사용 상황과 맞춰야 화면 우선순위와 성공 기준이 맞게 잡힌다

## 결과
- 2주차 가구 코드와 테스트를 그대로 쓴다.
- 4주차 화면은 처음 로그인하면 바로 내 냉장고를 쓰는 흐름을 먼저 만들고, 초대는 설정 화면에 둔다.
