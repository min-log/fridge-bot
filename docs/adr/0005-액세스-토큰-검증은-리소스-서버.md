# 0005. 액세스 토큰 검증은 Spring Security 리소스 서버에 맡긴다

- 상태: 채택
- 날짜: 2026-11-25

## 배경
API 요청마다 `Authorization: Bearer` 액세스 토큰을 검증해야 한다.

## 결정
- `spring-boot-starter-security-oauth2-resource-server`를 쓰고 `JwtDecoder`(HS256, 발급자 `fridge-bot` 검증)만 빈으로 등록한다.
- 발급은 같은 키로 만든 `JwtEncoder`(Nimbus)로 한다. 키는 `JWT_SECRET`(Base64, 32바이트 이상)이며 짧으면 앱이 뜨지 않는다.
- 컨트롤러는 `@CurrentUserId Long userId`로 토큰의 subject를 받는다 (`@AuthenticationPrincipal` 메타 애너테이션).
- 인증·인가 실패는 로그인 페이지로 리다이렉트하지 않고 항상 401·403 ProblemDetail JSON을 돌려준다.

## 검토한 대안
- 직접 만든 `OncePerRequestFilter` + JWT 라이브러리: 서명·만료·발급자 검증과 오류 응답을 모두 직접 관리해야 한다.

## 결과
- 검증 로직을 직접 작성하지 않고 표준 구현에 맡긴다. 401 응답에 `WWW-Authenticate: Bearer`가 붙는다.
- 나중에 비대칭 키(RS256)로 바꿀 때 `JwtEncoder`/`JwtDecoder` 빈만 바꾸면 된다.
