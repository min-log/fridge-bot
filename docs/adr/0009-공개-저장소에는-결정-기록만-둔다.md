# 0009. 공개 저장소에는 결정 기록만 두고 회고는 따로 관리한다

- 상태: 채택
- 날짜: 2026-11-25

## 배경
1주차에 AI가 작성한 회고 초안을 그대로 공개 저장소에 올렸다. 회고에는 한 일, 결정, 막힌 점, 개인적인 메모가 섞여 있었고, 공개할 필요가 없는 내용도 포함됐다.

## 결정
- 공개 저장소의 문서는 기획, 설계, 결정 기록(ADR), AI 활용 방식, 측정 결과로 한정한다.
- 기술 결정은 `docs/adr/`에 결정 하나당 파일 하나로 남긴다.
- 주간 회고와 개인 메모는 저장소에 올리지 않는다 (`.gitignore`로 제외한 폴더에서 관리).
- 이미 올라간 기록을 남기지 않기 위해, 공개 초기(스타·포크 0개)에 저장소를 새로 만들어 기록을 정리했다.

## 검토한 대안
- 회고를 계속 공개: 작업 과정을 보여 줄 수 있지만, 결정과 개인 메모가 섞여 읽는 사람이 판단 근거를 찾기 어렵다.
- 파일만 수정하고 기록은 유지: git 기록과 PR에 이전 내용이 계속 남는다.

## AI 제안과 내 결정
- AI 제안: 주차별 회고 파일(한 일·결정·막힌 점·다음 주)을 공개 저장소에 둠
- 내 결정: 공개할 문서의 범위를 다시 정하고, 결정 기록만 공개
- 다르게 한 이유: 공개 저장소는 읽는 사람이 판단 근거를 빠르게 찾을 수 있어야 하고, 개인 메모는 공개할 대상이 아니다

## 결과
- 문서마다 역할이 하나다: 기획(왜), 설계(무엇을), ADR(왜 이렇게), AI 활용(어떻게 만들었나), 결과(얼마나).
- 공개 전 확인 항목은 `CLAUDE.md`에 규칙으로 적어 AI 작업에도 적용한다.
