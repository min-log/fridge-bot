# 0001. 비밀값은 기본값 없이 환경변수로만 받는다

- 상태: 채택
- 날짜: 2026-11-25

## 배경
저장소를 처음부터 공개로 운영한다. `application.yml`에 `${KEY:기본값}` 형태로 기본값을 두면 실제 키가 기본값 자리에 들어가 커밋될 수 있다.

## 결정
- `application.yml`에는 키·접속 정보의 기본값을 두지 않는다.
- DB·Redis는 Spring 표준 환경변수(`SPRING_DATASOURCE_*`, `SPRING_DATA_REDIS_*`)를 그대로 쓰고 yml에는 아예 적지 않는다.
- 그 밖의 값(`JWT_SECRET`, `GOOGLE_CLIENT_ID` 등)은 `${NAME}`처럼 참조만 둔다. 값이 없으면 앱이 뜨지 않는다.
- 테스트용 가짜 값은 `src/test/resources/application-test.yml`에만 둔다.
- `.env.example`은 빈 값으로 커밋하고, `.env*`·`*.pem`·`*.key`는 `.gitignore`로 막는다. 모든 PR에서 gitleaks를 돌린다.

## 검토한 대안
- `${DB_URL}`처럼 모든 값을 yml에서 참조: 테스트에서 Testcontainers가 접속 정보를 넣어 줘도 참조 자체가 풀리지 않아 오류가 난다. 표준 이름을 쓰면 yml에 적을 필요가 없다.
- 개발용 기본값 허용: 편하지만 실수로 실제 값이 들어갈 자리가 생긴다.

## 결과
- 설정 파일만 봐서는 어떤 비밀값도 알 수 없다.
- 로컬 실행 전에 `.env`를 채워야 한다 (README에 방법 기록).
