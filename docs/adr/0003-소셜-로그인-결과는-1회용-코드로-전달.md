# 0003. 소셜 로그인 결과는 1회용 코드로 넘기고 토큰은 POST로 교환한다

- 상태: 채택
- 날짜: 2026-11-25

## 배경
OAuth2 로그인이 끝나면 백엔드가 프론트 주소로 리다이렉트해야 한다. 이때 토큰을 `?token=...`으로 실으면 브라우저 기록, 서버·프록시 접근 로그, Referer 헤더에 토큰이 남는다.

## 결정
- 로그인 성공 시 32바이트 임의 코드를 만들어 Redis `login:code:{code}`에 사용자 ID와 함께 60초 동안 저장한다.
- 프론트로는 `/oauth/callback?code=...`만 넘긴다.
- 프론트는 `POST /api/auth/token {code}`로 토큰을 받는다. 코드는 Redis `GETDEL`로 읽는 순간 지워져 한 번만 쓸 수 있다.
- OAuth2 state 보관에 쓴 세션은 로그인이 끝나면 바로 무효화한다.

## 검토한 대안
- 토큰을 URL 쿼리로 전달: 가장 간단하지만 위의 노출 문제가 있다.
- URL 프래그먼트(`#token=`): 서버 로그에는 안 남지만 브라우저 기록에는 남고, 액세스 토큰이 그대로 노출된다.
- 리다이렉트 응답에서 바로 쿠키 설정: 백엔드와 프론트 도메인이 다른 개발 환경에서 SameSite 처리가 복잡해진다.

## 결과
- URL에 남는 값은 60초 안에 한 번만 쓸 수 있는 코드뿐이다.
- 프론트 콜백 화면에서 요청이 한 번 더 필요하다.
- 테스트: 같은 코드 두 번째 교환 시 401 (`AuthFlowIntegrationTest`).
