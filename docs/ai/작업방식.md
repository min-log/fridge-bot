# AI 활용 방식

Claude Code를 개발 도구로 쓴다. 무엇을 만들지, 구조를 어떻게 할지는 사람이 정하고, AI에게는 정해진 범위의 구현과 초안 작성을 맡긴다.

## 1. 역할 나누기

| 사람이 정하는 것 | AI에게 맡기는 것 |
|---|---|
| 문제 정의, 범위, 하지 않을 것 ([기획](../00_기획.md)) | 코드 작성, 테스트 작성 |
| 기술 선택과 버린 대안 ([설계](../01_설계.md)) | 설계 초안, 대안 비교표 초안 |
| 결정 채택·거절 ([ADR](../adr/README.md)) | 결정 기록 초안 |
| 공개 범위, merge 여부 | 문서 정리, 반복 작업 |

AI가 낸 초안은 사람이 읽고 채택·수정·거절한다. 사람이 다르게 판단한 경우는 ADR의 "AI 제안과 내 결정"에 남긴다.

## 2. 컨텍스트 먼저 주기

작업을 시작할 때 AI가 먼저 읽는 문서를 정해 둔다.

- [`CLAUDE.md`](../../CLAUDE.md): 구조, 명령, 코드 규칙, 비밀값·공개 문서 규칙
- 기획 → 설계 → 관련 ADR 순서

## 3. 작업 단위

- 설계의 주차별 목표를 **PR 하나에 기능 하나** 크기로 나눈다.
- 한 번에 "로그인 만들어줘"처럼 통째로 맡기지 않는다. 지시할 때 단계(예: 스키마 → 토큰 발급·검증 → 업무 규칙 → 통합 테스트)와 단계별 완료 조건을 함께 준다.
- 1·2주차는 이 형식을 정하기 전에 진행했다. 2주차는 짧은 지시로 시작했고 단계는 AI가 나눴다. 3주차부터 아래 형식으로 지시하고, PR의 "AI 활용"에 지시 내용을 남긴다.

## 4. 지시 형식

```
목표: 무엇을 왜 (기획·설계의 어느 항목)
범위: 이번에 할 것 / 하지 않을 것
참고: 따를 ADR, 기존 코드 패턴
완료 조건: 통과해야 할 테스트, 확인할 시나리오
측정: (해당하면) 기록할 숫자
```

예시 (2주차 인증을 이 형식으로 쓴다면):
```
목표: 설계 2.1 인증 — 구글·카카오 로그인, JWT, 리프레시 토큰
범위: 백엔드만. 프론트 화면은 4주차
참고: ADR 0001(비밀값), 설계 4장 Redis 키
완료 조건: 로그인 코드 1회 사용, 리프레시 회전 후 이전 토큰 401,
          다른 가구 구성원 접근 거부를 통합 테스트로 확인
```

## 5. 검토 체크리스트 (AI 결과를 merge하기 전)

- [ ] 설명할 수 없는 코드가 없는가 (왜 이 방식인지 말할 수 있는가)
- [ ] 완료 조건의 테스트가 실제로 그 시나리오를 검증하는가 (테스트가 항상 통과하게 짜이지 않았는가)
- [ ] 설계·ADR과 다른 부분이 있으면, 의도한 것인가
- [ ] 비밀값·개인 정보가 들어가지 않았는가 (gitleaks로도 확인)
- [ ] 문서에 사실과 다른 내용이 없는가 (AI의 가정이 사실처럼 적혀 있지 않은가)
- [ ] 라이브러리 버전·API가 실제로 존재하는가 (컴파일·CI로 확인)

틀린 것을 찾으면 [검증기록](검증기록.md)에 남긴다.
